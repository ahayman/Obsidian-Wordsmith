# PONS Dictionary API Research

**Date:** 2026-02-05
**Purpose:** Comprehensive documentation of the PONS Online Dictionary (POD) API for potential integration into Obsidian Wordsmith plugin.

---

## 1. Overview

The PONS Online Dictionary (POD) API provides programmatic access to PONS's extensive dictionary database, offering:

- **12+ million headwords and phrases** across multiple languages
- **13 languages** supported
- **34+ language pair combinations** for translation
- **Definitions, translations, synonyms, example sentences**, phonetics, and grammatical information

The API integrates the complete PONS search engine into third-party applications, returning results in JSON format.

### Key Features
- Bidirectional translation lookup (e.g., German-English works both ways)
- Word gender and grammatical class information
- Phonetic transcriptions (IPA)
- Example sentences in context
- Fuzzy matching for typo tolerance
- Reference lookups for related entries

- Requires registration on PONS.com
- One API key per project/application
- Must apply separately for each website, app, or application

### Paid Tier
- **3.00 EUR per 1,000 requests** (standard rate)
- Custom pricing available for:
  - Flat fee arrangements
  - Limited dictionary access packages
  - Enterprise volume discounts

### Rate Limit Enforcement

- Contact: rights@pons.de for increased limits or custom pricing

- No automated queries without written approval
- No sublicensing or creating competing services
- No use on sites with illegal, adult, or extreme political content
- Service provided "as is" with no uptime guarantees

## 3. Authentication

### Method
The PONS API uses a custom HTTP header for authentication.

### Required Header
```
X-Secret: <your-api-key>
```

### Obtaining an API Key
1. Register an account at [pons.com](https://pons.com)
2. Navigate to the [API registration page](https://en.pons.com/p/online-dictionary/developers/api)
3. Complete the API registration form
4. Receive your unique API key (called "secret")

### Important Notes
- One access code is valid for **one project only**
- Separate applications require separate API key registrations
- API keys should be kept confidential and not shared

## 4. Endpoints

### Base URL
```
https://api.pons.com/v1
```

### 4.1 Get Available Dictionaries

Retrieves the list of all available dictionary combinations.

**Endpoint:**
```
GET /dictionaries
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `language` | string | No | Output language for labels (ISO 639-1). Default: `en` |

**Example Request:**
```bash
curl -X GET "https://api.pons.com/v1/dictionaries?language=en" \
  -H "X-Secret: YOUR_API_KEY"
```

**Example Request (wget):**
```bash
wget -O - --no-check-certificate "https://api.pons.com/v1/dictionaries?language=es"
```

---

### 4.2 Dictionary Query (Main Lookup)

Searches for a word or phrase in a specified dictionary.

**Endpoint:**
```
GET /dictionary
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `q` | string | Yes | Search term (URL-encoded UTF-8) |
| `l` | string | Yes | Dictionary identifier (e.g., `deen`, `enfr`) |
| `in` | string | No | Source language direction (e.g., `de` or `en` for `deen` dictionary) |
| `language` | string | No | Output language for labels (ISO 639-1). Default: `en` |
| `fm` | integer | No | Fuzzy matching: `1` to enable typo tolerance |
| `ref` | boolean | No | Include references: `true` for related entries |

**Example Requests:**

Basic lookup:
```bash
curl -X GET "https://api.pons.com/v1/dictionary?q=Haus&l=deen" \
  -H "X-Secret: YOUR_API_KEY"
```

With source language specified:
```bash
curl -X GET "https://api.pons.com/v1/dictionary?q=house&l=deen&in=en" \
  -H "X-Secret: YOUR_API_KEY"
```

Multi-word phrase:
```bash
curl -X GET "https://api.pons.com/v1/dictionary?q=to%20care%20for&l=deen" \
  -H "X-Secret: YOUR_API_KEY"
```

With references enabled:
```bash
curl -X GET "https://api.pons.com/v1/dictionary?q=went&l=deen&ref=true" \
  -H "X-Secret: YOUR_API_KEY"
```

With fuzzy matching:
```bash
curl -X GET "https://api.pons.com/v1/dictionary?q=hause&l=deen&fm=1" \
  -H "X-Secret: YOUR_API_KEY"
```

## 5. Request Format

### URL Encoding
- Search terms must be **URL-encoded UTF-8**
- Spaces should be encoded as `%20`
- Special characters must be properly escaped

### Dictionary Identifier Format
The `l` parameter uses a concatenation of two ISO 639-1 language codes:
- First code: One language in the pair
- Second code: Other language in the pair

Examples:
- `deen` = German-English (bidirectional)
- `enfr` = English-French (bidirectional)
- `dees` = German-Spanish (bidirectional)
- `enes` = English-Spanish (bidirectional)

### Bidirectional Behavior
When querying `deen` dictionary:
- Searching "Haus" returns German-to-English translations
- Searching "house" returns English-to-German translations
- Use `in` parameter to explicitly specify source language direction

## 6. Response Format

### Content Type
```
Content-Type: application/json; charset=utf-8
```

### 6.1 Dictionaries Endpoint Response

Returns an array of available dictionary objects.

```json
[
  {
    "key": "deen",
    "simple_label": "German «» English",
    "directed_label": {
      "de": "German » English",
      "en": "English » German"
    },
    "languages": ["de", "en"]
  },
  {
    "key": "enfr",
    "simple_label": "English «» French",
    "directed_label": {
      "en": "English » French",
      "fr": "French » English"
    },
    "languages": ["en", "fr"]
  }
]
```

**Field Descriptions:**

| Field | Type | Description |
|-------|------|-------------|
| `key` | string | Dictionary identifier used in `l` parameter |
| `simple_label` | string | Human-readable bidirectional label |
| `directed_label` | object | Language-specific directional labels |
| `languages` | array | Array of language codes in this dictionary |

---

### 6.2 Dictionary Query Response

The response contains an array with objects for each language direction.

#### Full Entry Response (type: "entry")

```json
[
  {
    "lang": "de",
    "hits": [
      {
        "type": "entry",
        "opendict": false,
        "roms": [
          {
            "headword": "Haus",
            "headword_full": "<span class=\"headword\">Haus</span> <span class=\"phonetics\">[haʊ̯s]</span> <span class=\"wordclass\">NOUN</span> <span class=\"genus\"><acronym title=\"neuter\">nt</acronym></span>",
            "wordclass": "noun",
            "arabs": [
              {
                "header": "1. Haus (Gebäude):",
                "translations": [
                  {
                    "source": "<strong class=\"headword\">Haus</strong>",
                    "target": "house"
                  },
                  {
                    "source": "ein <strong class=\"headword\">Haus</strong> bauen",
                    "target": "to build a house"
                  }
                ]
              },
              {
                "header": "2. Haus (Zuhause):",
                "translations": [
                  {
                    "source": "zu <strong class=\"headword\">Hause</strong>",
                    "target": "at home"
                  }
                ]
              }
            ]
          }
        ]
      }
    ]
  }
]
```

#### Translation-Only Response (type: "translation")

For simpler entries without full dictionary structure:

```json
[
  {
    "lang": "de",
    "hits": [
      {
        "type": "translation",
        "opendict": true,
        "source": "Hallo",
        "target": "Hello"
      }
    ]
  }
]
```

#### Reference Response (ref=true, type: "entry_with_secondary_entries")

When `ref=true` is specified:

```json
[
  {
    "lang": "en",
    "hits": [
      {
        "type": "entry_with_secondary_entries",
        "primary_entry": {
          "headword": "go",
          "headword_full": "...",
          "wordclass": "verb",
          "arabs": [...]
        },
        "secondary_entries": [
          {
            "headword": "went",
            "wordclass": "verb",
            "arabs": [...]
          }
        ]
      }
    ]
  }
]
```

---

### 6.3 Response Field Reference

#### Top Level
| Field | Type | Description |
|-------|------|-------------|
| `lang` | string | Source language code defining the direction |
| `hits` | array | Array of matching entries |

#### Hit Object
| Field | Type | Description |
|-------|------|-------------|
| `type` | string | Entry type: `"entry"`, `"translation"`, or `"entry_with_secondary_entries"` |
| `opendict` | boolean | Whether entry comes from open dictionary (user-contributed) |
| `roms` | array | Array of ROM (roman numeral) entries - one per part of speech |
| `source` | string | Source text (for `type: "translation"` only) |
| `target` | string | Target text (for `type: "translation"` only) |

#### ROM Object
| Field | Type | Description |
|-------|------|-------------|
| `headword` | string | The dictionary headword (plain text) |
| `headword_full` | string | Full headword with HTML markup (phonetics, gender, etc.) |
| `wordclass` | string | Part of speech (noun, verb, adjective, etc.) - optional |
| `arabs` | array | Array of Arabic-numeral sections (numbered meanings) |

#### Arab Object
| Field | Type | Description |
|-------|------|-------------|
| `header` | string | Section header (numbered sense with context) |
| `translations` | array | Array of translation pairs |

#### Translation Object
| Field | Type | Description |
|-------|------|-------------|
| `source` | string | Source language text (may contain HTML) |
| `target` | string | Target language translation (may contain HTML) |

---

### 6.4 HTML Markup in Responses

The `headword_full`, `source`, and `target` fields may contain HTML markup:

```html
<!-- Phonetics -->
<span class="phonetics">[haʊ̯s]</span>

<!-- Word class -->
<span class="wordclass">NOUN</span>

<!-- Gender (for gendered languages) -->
<span class="genus"><acronym title="neuter">nt</acronym></span>
<span class="genus"><acronym title="masculine">m</acronym></span>
<span class="genus"><acronym title="feminine">f</acronym></span>

<!-- Headword emphasis -->
<strong class="headword">Haus</strong>

<!-- Flexion information -->
<span class="flexion">&lt;-es, Häuser&gt;</span>

<!-- Style/register labels -->
<span class="style">informal</span>
<span class="rhetoric">figurative</span>
```

**Recommendation:** Strip HTML tags for plain text display, or parse specific classes for rich formatting.

## 8. Error Handling

### HTTP Status Codes

| Code | Status | Meaning |
|------|--------|---------|
| 200 | OK | Request successful, results found |
| 204 | NO CONTENT | Request successful, no results found |
| 403 | NOT AUTHORIZED | Invalid API key or access denied |
| 404 | NOT FOUND | Dictionary identifier does not exist |
| 500 | INTERNAL SERVER ERROR | Server-side error |
| 503 | SERVICE UNAVAILABLE | Rate limit exceeded (daily/monthly quota reached) |

### Error Response Format

For error responses, the body may be empty or contain a simple error message.

### Handling Guidelines

```javascript
async function queryPONS(word, dictionary) {
  const response = await fetch(
    `https://api.pons.com/v1/dictionary?q=${encodeURIComponent(word)}&l=${dictionary}`,
    { headers: { 'X-Secret': API_KEY } }
  );

  switch (response.status) {
    case 200:
      return await response.json();
    case 204:
      return { results: [], message: 'No results found' };
    case 403:
      throw new Error('Invalid API key or unauthorized access');
    case 404:
      throw new Error(`Dictionary '${dictionary}' does not exist`);
    case 503:
      throw new Error('Rate limit exceeded. Try again later.');
    default:
      throw new Error(`API error: ${response.status}`);
  }
}
```

## 10. Integration Notes

### Quirks and Limitations

1. **No Dedicated Synonyms Endpoint**: PONS does not have a separate synonyms/thesaurus API endpoint. Synonyms may be included in translation entries as alternative translations but are not structured separately.

2. **HTML in Responses**: Many fields contain HTML markup. Plan for either:
   - Stripping HTML for plain text
   - Parsing specific classes for rich display
   - Using a sanitization library for security

3. **Bidirectional Results**: A single dictionary query may return results for both directions (e.g., `deen` returns both German-to-English and English-to-German matches). Use the `lang` field to filter by direction.

4. **Source Language Ambiguity**: For words that exist in both languages of a pair, use the `in` parameter to specify the source language explicitly.

5. **No Offline Mode**: All queries require internet connectivity; there is no offline dictionary download option.

6. **Rate Limit Response**: The 503 error indicates quota exceeded. Implement exponential backoff and user notification.

7. **Open Dictionary Entries**: Entries with `opendict: true` are user-contributed and may be less reliable than official entries.

### Best Practices

1. **Cache Responses**: Implement local caching to reduce API calls and improve performance. Consider MySQL or localStorage caching.

2. **URL Encode Properly**: Always URL-encode search terms, especially for phrases with spaces or special characters.

3. **Handle Empty Results**: 204 responses are normal for misspelled or unknown words. Consider enabling fuzzy matching (`fm=1`) as a fallback.

4. **Parse HTML Carefully**: Use a DOM parser or regex to extract specific information from HTML-formatted fields:
   - Phonetics: Look for `.phonetics` class
   - Gender: Look for `.genus` class with acronym title
   - Word class: Available as both plain `wordclass` field and in `headword_full`

5. **Respect Rate Limits**: Track your usage and implement proper error handling for 503 responses.

6. **Display Attribution**: Always include "Dictionary powered by PONS" with a link as required by terms of service.

### TypeScript Interface Definitions

```typescript
interface PONSDictionaryInfo {
  key: string;
  simple_label: string;
  directed_label: Record<string, string>;
  languages: string[];
}

interface PONSTranslation {
  source: string;
  target: string;
}

interface PONSArab {
  header: string;
  translations: PONSTranslation[];
}

interface PONSRom {
  headword: string;
  headword_full: string;
  wordclass?: string;
  arabs: PONSArab[];
}

interface PONSEntryHit {
  type: 'entry';
  opendict: boolean;
  roms: PONSRom[];
}

interface PONSTranslationHit {
  type: 'translation';
  opendict: boolean;
  source: string;
  target: string;
}

interface PONSReferenceHit {
  type: 'entry_with_secondary_entries';
  primary_entry: PONSRom;
  secondary_entries: PONSRom[];
}

type PONSHit = PONSEntryHit | PONSTranslationHit | PONSReferenceHit;

interface PONSLanguageResult {
  lang: string;
  hits: PONSHit[];
}

type PONSDictionaryResponse = PONSLanguageResult[];
```

### Sample Integration Code

```typescript
const PONS_API_BASE = 'https://api.pons.com/v1';

interface PONSConfig {
  apiKey: string;
  defaultDictionary?: string;
  outputLanguage?: string;
}

class PONSClient {
  private apiKey: string;
  private defaultDictionary: string;
  private outputLanguage: string;

  constructor(config: PONSConfig) {
    this.apiKey = config.apiKey;
    this.defaultDictionary = config.defaultDictionary || 'deen';
    this.outputLanguage = config.outputLanguage || 'en';
  }

  private async request<T>(endpoint: string, params: Record<string, string> = {}): Promise<T | null> {
    const url = new URL(`${PONS_API_BASE}${endpoint}`);
    Object.entries(params).forEach(([key, value]) => {
      url.searchParams.append(key, value);
    });

    const response = await fetch(url.toString(), {
      headers: { 'X-Secret': this.apiKey }
    });

    if (response.status === 204) return null;
    if (response.status === 403) throw new Error('Invalid API key');
    if (response.status === 404) throw new Error('Dictionary not found');
    if (response.status === 503) throw new Error('Rate limit exceeded');
    if (!response.ok) throw new Error(`API error: ${response.status}`);

    return response.json();
  }

  async getDictionaries(): Promise<PONSDictionaryInfo[]> {
    return this.request<PONSDictionaryInfo[]>('/dictionaries', {
      language: this.outputLanguage
    }) || [];
  }

  async lookup(
    term: string,
    dictionary?: string,
    options?: { fuzzy?: boolean; refs?: boolean; sourceLanguage?: string }
  ): Promise<PONSDictionaryResponse | null> {
    const params: Record<string, string> = {
      q: term,
      l: dictionary || this.defaultDictionary,
      language: this.outputLanguage
    };

    if (options?.fuzzy) params.fm = '1';
    if (options?.refs) params.ref = 'true';
    if (options?.sourceLanguage) params.in = options.sourceLanguage;

    return this.request<PONSDictionaryResponse>('/dictionary', params);
  }
}
```

## 12. Summary for Obsidian Wordsmith Integration

### Relevant Capabilities
- **Definitions**: Yes - full dictionary entries with multiple senses
- **Translations**: Yes - bidirectional with example sentences
- **Synonyms**: Limited - may appear in translation alternatives, no dedicated endpoint
- **Phonetics**: Yes - IPA transcriptions in `headword_full`
- **Word Class**: Yes - noun, verb, adjective, etc.
- **Gender**: Yes - for gendered languages (German, French, etc.)

### Limitations for Wordsmith
1. **Translation-focused**: Primarily designed for bilingual translation, not monolingual definitions
2. **No English-English**: Does not provide English definitions for English words (only translations to other languages)
3. **No Synonym API**: No dedicated thesaurus/synonym endpoint
4. **HTML Processing Required**: Response data includes HTML that needs parsing
5. **Low Free Tier**: 1,000 requests/month may be limiting for active users

### Recommendation
PONS API is excellent for **multilingual translation features** but may not be ideal as the primary source for English synonyms and definitions in Wordsmith. Consider combining with:
- A monolingual English dictionary API (e.g., Free Dictionary API, WordsAPI)
- A dedicated thesaurus API (e.g., Datamuse, Big Huge Thesaurus)

PONS would be valuable as an **optional multilingual module** for users who want translation capabilities.
